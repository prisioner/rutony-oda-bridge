# Участие в разработке

Начните с [README](README.md), [среды разработки](docs/project/development.md),
[архитектуры](docs/project/architecture.md) и [проверок](docs/project/quality.md).
Клон самостоятельный: соседние репозитории, личные заметки и установленный
RutonyChat не нужны для обычной сборки. Для агентской работы есть
[инструкции](AGENTS.md).

Опишите конкретную проблему, ожидаемое поведение и шаги воспроизведения.
Если в репозитории включены GitHub Issues/PR, используйте их для обычных
ошибок и предложений без чувствительных данных. Если они недоступны,
способ приёма изменений определяет владелец. Срок ответа не обещается.
Для уязвимости следуйте [SECURITY](SECURITY.md).

Работайте в отдельной ветке, сохраняйте изменения других авторов.
Используйте синтетические fixtures: не запускайте реальные платежи,
глобальные оповещения, Steam upload или установку в пользовательский
RutonyChat ради теста. Не коммитьте credentials, журналы, SDK, generated
пакеты или runtime-файлы; ignore не защищает уже tracked историю.

Перед передачей изменения выполните:

```powershell
./scripts/build.ps1 -Check
pwsh -NoProfile -File tests/publication.tests.ps1
pwsh -NoProfile -File scripts/check-publication.ps1
```

В описании изменения укажите проблему, результат, выполненные команды
и ограничения. Разделяйте PASS, FAIL и NOT RUN; synthetic native/HTTP tests
не подтверждают реальные сервисы или GUI. Для изменения поставки проверьте
allowlist и [восстановление](docs/project/delivery.md), для артефактов —
воспроизводимость из руководства разработки. Сохраняйте уведомления
авторства Aleksandr Klimenkov и текст [MIT](LICENSE).
