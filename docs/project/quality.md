# Качество и границы доказательств

Обязательная проверка из корня самостоятельного клона:

```powershell
./scripts/build.ps1 -Check
```

Она запускает:

- Ядро: деньги/валюта, фильтрация источников, совместимые ID и skip,
  байтовая фрагментация STOMP, UTF-8/content-length/escaping/лимиты,
  durable дедупликация, lease, неопределённость, повреждение журнала,
  fault injection Write/Flush и Windows DPAPI с синтетическими реквизитами.
- Настоящий loopback OAuth callback: понятная ошибка без временных кодов
  и этапов диагностики, отказ, неизвестная ошибка, HTML или зависшее тело
  ответа, сохранность действующего входа и успешная повторная попытка.
  Проверяется отсутствие code/state, token, Secret и error_description в статусе.
- Настоящий loopback HTTP/WebSocket: PKCE/state/callback/refresh,
  Host/Origin/токен/JSON, подписка, ACK/reconnect, барьер паузы,
  явные Resolve/Skip, persistence выбора источников и legacy settings.
- Изолированная цепочка parser → ledger → **реальный тонкий скрипт** →
  FakeRutony Donate/OnDonate → независимый общий subscriber: ru-RU,
  EUR 12.34, имя, текст, message_id и дедуп после переоткрытия журнала.
  Native InitParams дополнительно проверяет один явный HTML anchor панели,
  пользовательский порт, отсутствие включённой доставки и повторный Closing.
- UI lifecycle: запуск/остановка до входа, остановка при активной
  синтетической доставке, сохранение committed, повторное открытие
  порта/журнала и ACK без повторной native-доставки. Watchdog и rescue
  относятся только к тесту; production не бросает незавершённую очистку.
- Полный deadline успешных token/refresh/subscription bodies; shutdown с
  активным login и ожидающей паузой, включая настоящий HTTP callback и
  RuntimeHost на UI-потоке. Поздний результат не меняет credentials.
- STOMP: смешанные LF/CRLF, все размеры фрагментов, NUL по content-length,
  большой body по одному байту, coalesced frames, UTF-8 заголовков и границы.
  Heartbeat-only fake server не удерживает CONNECT/SUBSCRIBE дольше deadline.
- JS syntax, Release библиотеки и сборку изолированного PreviewHost.

Поведенческие тесты панели доступны отдельно без npm-зависимостей:

```powershell
node --test tests/control.test.mjs
```

Они выполняют настоящий `control.js` в Node VM с небольшим DOM/HTTP стендом:
OAuth feedback без эха параметров, busy/повторный submit, сохранность ещё
не отправленного Secret, ошибка и порядок refresh, dirty source selection,
enable/pause и явные resolve/retry. Проверяется поведение событий и запросов,
а не совпадение текста исходников. Это не визуальная проверка браузера.
При использовании версии build-скрипта только с JS syntax запустите их отдельно.

HTTP, WebSocket, файлы и DPAPI в тесте настоящие. OAuth-аккаунт,
брокер и native host — имитаторы. Очередь проверяется моделью broker
lifecycle, физический отказ диска — fault injection. Это не подтверждает
production ODA, настоящий RabbitMQ или поведение установленного RutonyChat.

Автоматические проверки не покрывают все варианты production OAuth/ACL,
повторной доставки и отказов ODA, а также физический отказ диска.
Ручной сценарий для своей установки — в [инструкции](../oda-setup.md).
Компиляция против выбранной RutonyChat.dll проверяет SDK, загрузка скрипта
и двойной клик Windows .url — поведение конкретной установки.
Не выполняйте платежи или глобальные тестовые донаты ради автоматической проверки.

Для UI используйте [изолированный стенд](development.md), проверяйте выбор
источников, сохранение, паузу и перезагрузку страницы. Для поставки
проверяйте ссылки, отсутствие внешних файловых зависимостей, секретов
и чужих файлов в пакете. Игнорируемые bin/obj/dist/runtime и личные
данные не входят в Git.

В отчёте об изменении указывайте выполненные команды и ограничения;
невыполненная проверка не означает успех.
