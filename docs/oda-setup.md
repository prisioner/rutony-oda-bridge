# ODA → RutonyChat: подключение

Мост передаёт выбранные донаты ODA в общий поток Donate/OnDonate RutonyChat.
События получают обычные оповещения и пользовательские скрипты программы.
Для подключения нужны своё OAuth-приложение ODA и права доступа к его очереди.
После настройки проверьте свою установку по сценарию ниже.

## 1. Установить пакет

1. Закройте RutonyChat.
2. Откройте папку установки через Steam → RutonyChat → Управление →
   Просмотреть локальные файлы.
3. Создайте в `scripts` папку `RutonyOda`. Скопируйте в неё
   `RutonyOda.dll`, `LICENSE` с текстом MIT и папку `web` из готового пакета
   `dist/RutonyOda`.
4. Файлы `rutony_oda.cs` и `rutony_oda.json` скопируйте прямо в `scripts`.
5. Запустите RutonyChat.

Для обновления рекомендуется установщик: он проверяет полный комплект до
замены файлов и при ошибке восстанавливает предыдущую версию. Распакуйте
**весь** пакет, включая `install.ps1`, `package-contract.ps1` и
`package-manifest.json`. При закрытом RutonyChat откройте PowerShell в папке
пакета и выполните, подставив папку установки:

```powershell
./install.ps1 -RutonyDirectory '<папка установленного RutonyChat>'
```

Копия всех прежних файлов моста сохраняется в
`scripts/.RutonyOda-install/<transaction-id>/backup`; перечень и прежние хэши —
в соседнем `snapshot.json`. Пользовательские настройки и журнал не заменяются.
SDK и Node для работы готового пакета не нужны.

Для установленного через Steam Workshop комплекта дождитесь загрузки Steam
и перезапустите RutonyChat. При переходе с ручной установки отключите прежний
пресет: на одном порту должен работать один экземпляр моста. Оставьте
`PackageDirectory` пустым и используйте прежний `DataDirectory`.
Состав и самостоятельная сборка комплекта описаны в
[техническом руководстве Workshop](https://github.com/prisioner/rutony-oda-bridge/blob/master/docs/workshop/README.md).

Если установка прервана или написано **ROLLBACK FAILED**, оставьте RutonyChat
закрытым, устраните причину ошибки (например, блокировку файла) и из **того же
сохранённого полного пакета** выполните:

```powershell
./install.ps1 -RutonyDirectory '<папка установленного RutonyChat>' -Recover
```

После успешного восстановления повторите обычную установку без `-Recover`.
Если восстановление не удалось, сохраните весь каталог transaction и
`active.json`; не удаляйте их ради обхода проверки. Замена нескольких файлов
не является атомарной: после прерывания может потребоваться этот шаг.

## 2. Включить скрипт и открыть панель

1. RutonyChat → Удалённое управление → Автономные скрипты.
2. Добавьте пресет `ODA` и выберите `rutony_oda.cs`.
3. В параметрах при обычной установке оставьте папки пустыми,
   порт — **18766**. Сообщения чата и события оповещений скрипту
   не требуются: обе галочки можно снять.
4. Поставьте **Включено**, сохраните и нажмите **Переподключить**.
5. Откройте в обычном браузере `http://127.0.0.1:18766/control`.

В пакете есть **Открыть ODA.url** для стандартного порта и **Панель ODA.html**
с одним полем порта. Их можно скопировать на рабочий стол. Они открывают
панель при работающем скрипте, запуск RutonyChat выполняется отдельно.
При включении скрипта в RutonyChat появляется ссылка **Открыть панель ODA**
с выбранным портом. Если пользовательская тема не показывает ссылки,
используйте ярлык из пакета. При смене порта измените адрес панели
и Redirect URI следующего шага.

## 3. Создать своё приложение ODA

1. Откройте [кабинет ODA](https://widgets.oda.digital/) под своим аккаунтом.
2. В API → Мои приложения создайте приложение, например `Rutony ODA bridge`.
3. Добавьте Redirect URI **http://127.0.0.1:18766/oauth/callback**
   без завершающего слеша. В панели моста показана строка с вашим портом.
4. Скопируйте Client ID и Client Secret в панель моста. Если секрет скрыт,
   кнопка обновления в ODA выпускает новый и делает старый недействительным;
   используйте отдельное приложение для моста.
5. Нажмите **Сохранить приложение**, затем **Войти / повторить вход**.
   Вход и пароль вводятся на странице ODA.
6. После возвращения дождитесь **Вход выполнен**, затем нажмите
   **Включить передачу**. Ожидается **Передача включена**, **Связь: есть**.

В **Какие донаты передавать** доступны ODA, DonationAlerts, DonatePay,
DonatePay.eu, Donate.Stream, DonateX, Tribute. По умолчанию только ODA.
Можно выбрать импортированные системы или снять все галочки. Сервис
сначала подключается к ODA отдельно: выбор в мосте фильтрует уже полученные
события. **Сохранить источники** ставит приём на паузу и сохраняет вход;
затем включите передачу. Уже пропущенные и ACK-подтверждённые сообщения
после изменения выбора не восстанавливаются.

### Если вход не завершён

Проверьте сообщение в верхнем блоке панели. Client ID и актуальный Client
Secret должны быть взяты из одного приложения ODA. После исправления
сохраните приложение и начните вход заново кнопкой панели в том же браузере
и на том же компьютере, где работает RutonyChat. Если секрет перевыпускали,
старый больше не подходит. Рабочие credentials и журнал удалять не нужно.

## 4. Настройки и реквизиты

Данные по умолчанию — `LocalAppData/RutonyOda` текущего Windows-пользователя.
`DataDirectory` в параметрах скрипта задаёт другой каталог.
`PackageDirectory` — расположение DLL/web. Непустой параметр имеет приоритет.
При пустом значении скрипт ищет зарегистрированный `rutony_oda.cs` через
`RutonyBotFunctions.GetScriptDirectory` и его подпапку `RutonyOda`.
Если lookup пустой или завершается ошибкой, используется ручной путь
`<RutonyChat>/scripts/RutonyOda`. Если item найден, но DLL отсутствует,
запуск завершится ошибкой. При наличии ручной и Workshop-копии
автоматический поиск выбирает Workshop; ручной путь можно задать явно.
Не размещайте `DataDirectory` внутри Workshop: обновление и отписка
управляют файлами item, а настройки и журнал должны сохраняться отдельно.

- `settings.json` хранит галочки `SourceSystems`, состояние передачи
  `Enabled` и `InstallationId`. В старых настройках без списка источников
  выбирается только ODA. Включённая передача и выбор переживают перезапуск.
- `credentials.bin` хранит Client ID, Client Secret, refresh/access token
  и срок действия, защищённые DPAPI текущего Windows-пользователя.
  Реквизиты не хранятся в settings.json. Другой Windows-пользователь
  не сможет расшифровать скопированный файл.
- `deliveries.jsonl` и маркеры `ledger.version`/`ledger.initialized`
  хранят состояние доставки. Полные сообщения, имена и токены
  в журнал доставки не записываются.

Обновление пакета не заменяет эти данные. Смена DataDirectory создаёт
другую историю и очередь; не используйте её как сброс ошибок. Сохранение
нового приложения выключает передачу и требует повторного входа.
Пользовательские credentials и журналы не отправляйте в репозиторий.

## 5. Ручная проверка настоящего доната

1. Проверьте, что тот же сервис не подключён одновременно через браузерный
   Rutony-виджет или второй мост. Общей дедупликации независимых входов нет.
2. Дождитесь следующего настоящего доната. Автоматическая проверка
   не выполняет платежей. Кнопка теста стороннего виджета может иметь
   другой формат и не доказывает доставку платежа.
3. Проверьте счётчик доставки в панели моста и обычный донат в RutonyChat.
   В стандартном интерфейсе источник может называться **Other**.
4. Проверьте имя, сумму, валюту, текст и нужный обычный обработчик OnDonate.

Если сервис уже подключён напрямую к RutonyChat, его одновременная передача
через ODA может дать повторы. Разные реальные ID одного имени сохраняются.
Слишком большие суммы, которые native float меняет до копейки, блокируются
с диагностикой. Реальные ACL, авторизация и native-доставка считаются
проверенными только после такого ручного прогона выбранной установки.

## Сбой, остановка и обновление

- **Пауза** дожидается начатой native-доставки и отключает consumer.
  Очередь рассчитана на 24 часа; полная история не восстанавливается.
- Неопределённая доставка означает, что RutonyChat мог уже обработать
  событие до записи результата. Проверьте оповещения и выберите
  **Уже доставлен — не повторять** либо **Разрешить повтор**.
  Затем включите передачу. Повтор может повторить оповещение.
- Некорректное сообщение ставит передачу на паузу. Явный
  **Пропустить проблемное сообщение** сохраняет только SHA-256 отпечаток;
  пропущенное событие не попадёт в RutonyChat.
- Ошибка HTTP: проверьте своё приложение, Redirect URI и повторите вход.
  Ошибка STOMP требует проверки scope `stomp` и прав внешнего клиента
  на подписку/очередь; production ACL не подтверждены локальным тестом.
- Повреждение журнала и ошибка диска блокируют передачу. Не удаляйте
  рабочие файлы ради старта. После ошибки записи текущий экземпляр
  заблокирован: переоткройте мост и проверьте данные без их удаления.
- Для полного выключения снимите **Включено** у ODA-пресета и нажмите
  **Переподключить**. Для обновления/отката закройте RutonyChat,
  замените пакет сохранённой версией и полностью перезапустите программу.

Локальные имитаторы не проверяют права вашего OAuth-приложения,
работу внешней очереди и особенности установленной версии RutonyChat.
После обновления проверьте панель и сохранённые настройки. Для Workshop
дождитесь окончания обновления Steam и перезапустите RutonyChat.
Перед отпиской отключите пресет; пользовательский каталог данных
сохраняйте отдельно от файлов item.


## Проверка изменения и остановки пресета

После обновления полностью перезапустите RutonyChat, чтобы загрузилась
новая DLL. В окне автономных скриптов измените название тестового пресета
и сохраните, затем выключите его и нажмите «Переподключить».
Интерфейс должен отвечать, локальная страница выключенного расширения
перестанет открываться. Включите пресет снова на прежнем порту:
страница и сохранённые данные должны быть доступны.
Удаление тестового пресета также проверяется отдельно; файлы данных
ради этого не удаляются. Это ручная проверка конкретной установки,
а не результат автоматического UI-context теста.
